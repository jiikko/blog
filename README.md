# blog.jiikko.com

This repository is being migrated from Lokka to a static site generated by Hugo and served by Cloudflare Pages (`https://blog-9oc.pages.dev` until the DNS switch in issue 010). The theme and the 173 public posts have been ported.

## Local preview

Install Hugo, then run:

```sh
hugo server --buildDrafts
```

Open the local URL printed by Hugo. Build the static site with:

```sh
hugo --minify
```

The generated site is written to `dist/`.

The GitHub Actions workflow in `.github/workflows/hugo.yml` runs this build for pull requests targeting `blog.jiikko.com`, pushes to `blog.jiikko.com`, and manual runs. It uses Hugo 0.170.0 and writes the output to `dist/`. Cloudflare Pages builds the same branch on every push (`hugo --gc --minify`, output `dist`, `HUGO_VERSION=0.170.0`, `SKIP_DEPENDENCY_INSTALL=1`) and publishes it; a build takes about 4 minutes because the Lokka `.ruby-version` still makes it compile Ruby (until issue 011).

## 記事の書き方（更新マニュアル）

1. 記事のファイルを作る。ファイル名がそのまま URL になる（`content/posts/my-post.md` → `https://blog.jiikko.com/my-post`）

   ```sh
   hugo new content posts/my-post.md
   ```

   - ファイル名は英小文字・数字・`-` で付ける。数字だけの名前（`211` など）は旧ブログの記事と同じ形なので使わない。`page` `category` `tags` `theme` `index` も、既にある URL とぶつかるので使わない
2. front matter を埋めて、本文を Markdown で書く

   ```toml
   +++
   title = "記事の題"
   date = "2026-11-26T23:19:50+09:00"     # 公開日時。記事ページと一覧の日付・並び順になる
   lastmod = "2026-11-26T23:19:50+09:00"  # 直したら更新する（feed と sitemap に出る）
   draft = true                           # 公開するときに false にする
   url = "/my-post.html"                  # 作ったときのまま触らない（/my-post で配信される）
   category = ["4"]                       # カテゴリーの番号。下の表から 1 つ
   tags = ["ruby"]                        # 自由に付ける。大文字小文字は書いたとおりに URL になる
   atom_id = ""                           # 空のままでよい
   +++
   ```

   | 番号 | カテゴリー | 番号 | カテゴリー |
   |---|---|---|---|
   | 1 | postfix | 7 | Kinesisキーボード |
   | 2 | dovecot | 8 | shell script |
   | 3 | ruby | 9 | aws |
   | 4 | 日記 | 10 | rails |
   | 5 | instance-email.com | 11 | MySQL |
   | 6 | 開発環境 | | |

   - 新しいカテゴリーを作るときは、`content/category/<新しい番号>/_index.md` に `title` を書く
   - 画像はこの repo に入れない。別の repo `jiikko/cdn` の `images/blog/YYYY/MM/DD/` に push し、本文には `https://raw.githubusercontent.com/jiikko/cdn/master/images/blog/YYYY/MM/DD/<ファイル名>` を貼る（issue 009）
   - コードブロックは色付けしない（旧ブログに合わせている）。生の HTML（埋め込みなど）も書ける
3. 手元で見た目を確かめる

   ```sh
   hugo server --buildDrafts
   ```

   表示された URL を開く。ファイルを保存すると自動で読み直される
4. 公開する。`draft = false` にしてから commit し、`blog.jiikko.com` ブランチに push する

   ```sh
   git add content/posts/my-post.md
   git commit -m "記事: 記事の題" -- content/posts/my-post.md
   git push origin blog.jiikko.com
   ```

   - **この repo は public なので、`draft = true` のまま commit しない**（サイトには出ないが、GitHub では誰でも読める）。書きかけの記事は commit しないで手元で持つ
   - push すると Cloudflare Pages が自動でビルドして公開する。反映まで 4 分ほどかかる。ビルドの結果は Cloudflare のダッシュボードの Workers & Pages → `blog` → Deployments で見られる
5. 直すときは、本文と `lastmod` を書き換えて同じように commit・push する。`date` と `url` は変えない（`date` を変えると feed で別の記事として扱われることがある）

## Content format

Posts belong in `content/posts/`. The 173 public Lokka posts were exported with `bin/export-lokka-entries` (run `bin/export-lokka-entries --help`). It reads a local MySQL copy restored from a `mysqldump` of `lokka_production`, writes one Markdown file per public post plus `content/category/<id>/_index.md`, and never writes to the database. Drafts and comments are not exported because this repository is public. Re-run it just before the DNS switch (issue 010) and check that `git diff` is empty.

Every Lokka post was written in Markdown (redcarpet, one in kramdown), so bodies are kept as the original Markdown. Each post keeps its legacy URL (`url`), its Lokka id (`lokka_id`), its category id (`category`, so `/category/<id>/` stays the same), its tags and the Atom ID the old feed used (`atom_id`). Posts are written as `/<name>.html`; Cloudflare Pages serves them at `/<name>`, the Lokka URL, and the templates link to that form. Tags keep their case (`disablePathToLower`), and list pages send old `?page=N` links to `/page/N/` with a small script in `layouts/baseof.html`. After a deploy, run `bin/check-legacy-urls <site origin>` (see `--help`) to request every Lokka-era URL and list the ones that do not answer 200. `hugo.toml` turns off Goldmark's typographer and code-fence highlighting so the output matches what redcarpet produced. New posts use Markdown by default. Hugo's Goldmark renderer also allows raw HTML in Markdown.

The existing Lokka application and ERB theme remain in the repository temporarily as migration references. Hugo uses the templates in `layouts/` and the copied public assets in `static/theme/blog.jiikko.com/`.
